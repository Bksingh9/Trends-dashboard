# QA — 2026-08-15

What was found, what was fixed, and what is still open. Written against the
running build, not the source.

## The pattern in almost everything below

Nine of the eleven defects here have the same shape: **code that reported
success while doing less than it claimed.** Not crashes — crashes get fixed.
These all rendered a plausible screen.

That is the failure this dashboard was commissioned over. `avis_base_view`
stopped reflecting new orders on 25 Jun 2026 and ran for two weeks *while
reporting itself as updating daily*. Every piece was individually correct; what
was missing was anything that looked across the seams.

None of these was visible in review. Most needed either a live credential or a
measurement in a real browser.

## Fixed

### 1. BigQuery reads returned one page — P0

`runQuery` posted to `jobs.query` and returned `json.rows`. That endpoint
returns at most the first page (50,000 rows, or fewer at the 10 MB ceiling) and
hands back a `pageToken`. The token was ignored.

A 6.5 M-row catalogue would have loaded 50,000 rows, filled the mart, passed its
assertions on what arrived, and reported `live`. Every EAN past the cut would
have classified as `absent_from_master` — the most alarming reason in the §20.3
taxonomy, and entirely an artefact of the read.

The same call read an incomplete job as an empty one: `timeoutMs` bounds the
request, not the query, so anything slower than 60 s returned `jobComplete:
false` with no rows and was recorded as a successful run over nothing.

Now paginates and polls. Truncation is **reported, not inferred** — a query
returning exactly `maxRows` and one cut off at `maxRows` are the same size.

### 2. A pasted credential could never be tested — P0

`config` is built once at import from `process.env`. "Test connection" sets
`GCP_SA_KEY_JSON` for the length of one call, so `serviceAccountKey()` never saw
it. Every GCP connection test failed with "GCP_SA_KEY_JSON not configured",
**including the ones holding a working key** — and the message blamed the
credential.

### 3. The OAuth token cache was shared across accounts — P0

One global. Test account A, then account B, and B returns A's token — reporting
"connected" for a credential that was never checked. Now keyed on
`client_email` + scopes.

### 4. Five source types were offered with nothing behind them — P0

`mysql`, `snowflake`, `rest-api`, `csv-url` and `gcs` appeared in the picker,
accepted a credential, stored it with a masked preview, and did nothing. All
implemented; a test now asserts `TESTS` covers `SOURCE_TYPES` in both
directions, and the eighteen SaaS families declare type and probe as one object
so the mistake is not expressible.

### 5. The type system had never once applied — P1

`next/font` set `--font-archivo` on `<body>`; Tailwind's `@theme` consumes it at
`:root`, one level above. Custom properties inherit downward, so the references
resolved to nothing and every element fell back to the system sans.

The functional loss was `.num`: every figure is meant to be IBM Plex Mono for
tabular numerals so columns line up digit over digit. In a proportional font
they do not, and a column of numbers you cannot scan is the reason for the
choice. Measured in the browser, not read in the source — the source was right.

### 6. A fork was being counted as a drop — P1

The first journey-discovery pass reported *"85% drop at Search"* for sessions
that had opened the scanner instead. They were still in the app and converting
better than the ones counted as retained. Every number in the sentence was
arithmetically correct and the sentence was false; it would have sent somebody
to debug a working screen.

Sessions are now split into carried-through / diverted / **exited**, and only
exits count as a hole.

### 7. The board's metric→module map was wrong in eight places — P1

Hand-written from expected ids rather than emitted ones. Eight tiles would have
read "not being published right now" — honest, useless, avoidable. A test now
runs every module and checks the map in both directions.

### 8. A trend plunged to zero on its most recent day — P1

`dateRange(w)` emits every calendar day and a day with no rows aggregates to
zero, so the newest point sat on the floor until its partition landed. A gap on
a page; at four feet of line on a wall display, a collapse — and it is the last
point on the chart, where the eye goes first.

### 9. `listDatasets` saw 16 of 242 datasets — P1

`INFORMATION_SCHEMA.SCHEMATA` is region-scoped. The connection test drew the
obvious conclusion from an incomplete list and reported "No analytics_* dataset
here", which was false — both GA4 exports were among the missing 226.

### 10. A null coordinate became 0 — P2

`Number(r.lat ?? 0)` put every store with no location in the Atlantic. §4.4's
map would have plotted phantoms instead of reporting that the store master has
no location for them.

### 11. `open_close_ratio` rendered as a percentage — P2

Declared `unit: 'ratio'`, which in this registry means 0–1 and renders as a
percentage. 1.5 issues opened per closed printed as **"150%"**, which reads as
a share and is not one. Caught by the new reconciliation suite's "every rate is
inside 0–1" check — the point being that a unit is a claim about a number.

## Built

- **§4.4 store map** — cities sized by store count, dark share filled in.
  Stores with no coordinates are listed underneath, not dropped.
- **§4.3 `time_to_order_p50`** — was permanently `missing`; `fact_journey_path`
  is the session-level extraction it was waiting for. 413,000 ms.
- **§9.6 CSV export** on every captioned table — raw values, not rendered ones,
  so a column can be summed. Leading zeros survive Excel.
- **§4.9 Browse BigQuery** — 242 datasets, metadata only, zero bytes scanned.
- **§4.10 Board** — seven tile kinds; tiles render §5 metrics and cannot compute.
- **§4.11 Help & Support analytics** — GA4 Data API, server-only.
- **§18.4/18.5 Slack bridges** — snapshot read and webhook write, both reporting
  `cache` rather than `live`.
- **Reconciliation suite** — 18 cross-surface checks.

## Counts

435 unit tests, 30 E2E, lint and build clean.

The number that matters more: **eleven defects, nine of which reported success.**
Every one is now covered by a test that fails if it returns — because the ones
that look like working software are the ones that come back.
